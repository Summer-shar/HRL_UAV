# v33 重置试验协议

> 状态：PILOT。v24-v32 结果与配置保留，仅停止沿用其硬功率门槛和统一方向用户移动设定。

## 1. 试验目标

v33 首先回答两个基础问题：

1. 在物理可行的负载下，微观 SAC 能否学到稳定的协作转发，使队列不持续增长；
2. 在微观层稳定后，宏观 TD3 是否能进一步改善端到端时延，而不是让轨迹漂移并破坏队列。

功率是次要优化项和监测项，不再要求低于某个预设瓦数。只要训练后期功率不持续上升，且时延和队列改善，即认为能耗行为可接受。

## 2. 环境口径

- 3 架 UAV、39 个地面用户、每架 UAV 最高 10 GHz；
- 三阶段区域负载循环为 `[12.5, 5.5, 3.5]`、`[3.5, 12.5, 5.5]`、`[5.5, 3.5, 12.5]` Mbit/s；
- `load_scale=1.0`，总到达率为 21.5 Mbit/s；
- 每个 10 秒宏观周期有 1 秒部署停服，有效总计算能力约为 27 Mbit/s，系统利用率约 79.6%；
- 每个负载阶段恰有一个区域的本地到达率超过单机有效算力，因此必须使用 UAV 间协作转发；
- CPU 使用 `priority_demand`：先满足高优先级队列，再将剩余频率分给低优先级队列；不设置系统级 CPU 功率夹断；
- 每名用户在 episode 开始时独立采样长期平均移动方向，之后按 Gauss-Markov 模型随机漂移；取消所有用户共享同一东北方向的历史设定，也不使用区域圆形边界钳位。

## 3. 优化目标

采用固定软加权目标：

`J = 0.9 * normalized_delay + 0.1 * normalized_energy`

- 不使用 840 W 或其他硬预算；
- 不使用动态乘子 lambda；
- 不使用固定功率违约惩罚；
- 主要评价端到端时延和队列积压，功率仅作为趋势与代价报告。

## 4. 两阶段训练

### 阶段 A：微观 SAC（300 episodes）

- 宏观动作固定为联合零残差；
- `centroid_waypoint` 下，零残差表示每架 UAV 因果跟踪本区域当前业务质心；
- 宏观 PPO 参数不训练，其随机初始化输出也不参与环境动作；
- 只训练 SAC 路由策略，并用固定评估种子记录整系统时延、队列、功率和微观奖励。

### 阶段 B：联合 HRL（1000 episodes）

- 从阶段 A 的 SAC checkpoint 开始；
- TD3 学习相对业务质心的宏观残差轨迹；
- SAC 继续以较小学习率更新，使下层能够适应上层改变后的通信几何；
- 收敛图使用连续横轴：1-300 为微观阶段，301-1300 为联合阶段，并用背景分区标明阶段，不再画成两条互不相干的主曲线。

## 5. 启动与停止判据

阶段 A 结束前必须确认：

- 固定评估种子下，端到端时延进入平台区而非持续恶化；
- 周期负载切换下，同相位的周期边界队列没有持续增长；
- 功率曲线不存在随训练轮数持续上升的趋势。

任一项不满足，则先诊断微观 SAC，不启动宏观联合训练。阶段 B 使用相同三项指标判断整体收敛；checkpoint 仅用于保存和复现，不用早期偶然点掩盖后期发散。
