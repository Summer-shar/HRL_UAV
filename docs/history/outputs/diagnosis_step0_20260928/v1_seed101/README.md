## “只训 SAC”并不意味着 UAV 悬停

这条 v1 的 PPO 更新为 **0**，但上层执行的是**动态需求质心规则**。

- 指纹匹配的 `learning.py:195–199`：禁用上层网络时返回零残差动作。
- 历史 `mdp.py:238–251`：`target = weighted_centroids + waypoint_radius_m * offset`，每次位移上限 20 m。
- 因此零残差对应追随当前加权质心，而不是维持当前 UAV 坐标。`pairing_audit.csv` 验证各评价方法的质心和几何轨迹一致。

当前 v2 的前 300 轮和 G1 使用悬停；这是需要在解释结果时明确列出的协议差异。旧 SAC 成功没有依赖学会 PPO；它也不能直接证明移动轨迹已经正确，更不能把“PPO 没训练”说成“没有移动”。

## 实际训练量需要拆开比较

| 累计量 | v1 window 2000 | v2 ep300 |
|---|---:|---:|
| critic 梯度拟合次数（两 Q 合并一次计数） | 53,951 | 53,820 |
| actor 更新次数 | 26,925 | 13,410 |
| target 更新次数 | 53,951 | 26,910 |
| 写入过的 replay transition 数 | 1,080,000 | 540,000 |
| 训练窗口内物理时长 | 600,000 s | 270,000 s |
| 窗口数及长度 | 2000 × 300 s | 300 × 900 s |

**critic 拟合总量几乎相等，但旧 actor 更新和经验量约为新的一倍以上。** 所以不能简单用“旧 2000、新 300”断言训练次数差 6.7 倍，也不能因 critic 拟合次数相等便说学习预算相等。这里不据此修改当前训练日程或恢复训练。

旧 `boundary_audit.csv` 与 pilot 的同名记录合计 667 条独立物理流：666 条完整 900 s 流、最后一条 600 s。每流只 reset 一次，每流另推进 1 s 部署尾部以补全 pending transition，故实际环境推进总时长为 **600,667 s**；其中 667 s 尾部不计入窗口结果。30 宏步 × 每宏 18 次下层动作 = 每 300 s 窗口 540 条经验，恰好核对为 1,080,000 条。

v2 计数来自 300 行 `train_metrics.jsonl` 求和：27,000 次触发、90 次空回放跳过、26,910 次 SAC 事件，每事件两次 critic fit；物理步为 2,700,000 × .1 s。经验总生成数由每窗口 1800 条计算，**不是最后 replay 仍保留的容量**。
