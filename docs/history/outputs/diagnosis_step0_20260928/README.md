# 第 0 步诊断：旧 SAC 成功记录与当前 ep300 失败

本次保留原场景、源码、配置、模型及 G1 判定。新增冻结评价与脚本控制共 **360000 个物理步，0 次训练更新、0 次回放写入**；没有启动或恢复训练。研究源码提交仍为 `4f8198ac1e0ce391b2860cfbbfa896f5412a73ce`。所有新脚本、数据和说明均在本输出目录。

结论：**旧 v1 SAC 的成功有实验记录支持；当前 v2 的确定性 SAC 也在 16/20 场景胜过三等分。问题应表述为随机执行放大风险、少数场景路由失效，以及版本差异尚未定位，不能概括为 SAC 学不会或场景没有下层信号。** 本次没有单因素训练消融，不能确认某一项为学习失败的唯一根因。

随机 SAC 改为确定性执行后平均时延降低约 43.94%，但仍比三等分高 17.03%。这量化了执行分布的影响，尚未隔离 support 采样与条件比例采样各自的贡献，不能全部称作“比例噪声”。

关键尾部案例：

## 3. 熵解释：条件性偏置存在，不能说单点免费

当前每行期望正则为 `KL(q || Uniform7) + sum_s q(s) KL(Dirichlet_s || UniformFace_s)`。确定选一个单目的 support 的连续项为 0，但离散项是 `log(7)=1.945910` nat。精确多目的分流会多付连续 KL，因此在给定分布精度时可能倾向更便宜的 support；这不等价于“无价值差时必然坍缩”。若 support 和 face 都趋于参考均匀分布，总 KL 可以趋于 0。

实际审计最终 actor 在 55 个训练 episode 的 715 个真实回放状态：

- 多目的各坐标浓度最高约 22.05，并非假设的 100；三条低优行出现某单目的 support 概率 >99% 的状态分别为 43、13、33 个，高优行为 0。
- 六行合计平均 KL：离散 5.609281 nat、连续 0.985922 nat。按 ep300 alpha=.0005，单步期望正则约 .0032976；这是选定训练状态的解析统计，不能直接当作开发失败的因果解释。
- 对 Dirichlet(100,100,100)，均值处连续 log density ratio 为 4.818454 nat，真正的期望 KL 为 3.826254 nat；两个量不同。

详见 [逐行熵与浓度审计](entropy/README.md)。这次未测拥塞状态下 critic 对反事实路由的排序，也没有熵消融训练。将低优价值差简单视为高优的十分之一同样没有验证，因为两优先级共享队列与资源。去掉连续项属于修改学习目标，而不是恢复一个已经证明损坏的等价实现。

## 4. v2_2_2 的决策顺序（本次未实施）

1. **保留场景。** 先处理当前少数场景的失效，尤其场景 9 的 CPU 路由拥堵，不能用全体平均掩盖它。后续若继续诊断，应结合该轨迹上的真实动作、support、目标 CPU 工作量和 critic 对可行替代动作的排序；critic 排序本身仍需实际后果校验。
2. **预先明确部署及评价口径。** 若实际使用确定性路由，可为新版本注册确定性主评价、随机执行压力评价，两者都保存。旧 G1 保持原判定。不要仅因确定性结果较好就称原随机评价“不公平”；它测的是另一种部署行为。
3. **将初始化、正则、更新配置分开比较。** 旧版 Gaussian 投影与新版 Hybrid 有多处变化，当前资料不能唯一归因到熵。equal 附近初始化有明确动机；删连续熵或单独 alpha 则改变优化目标。先选择一项受控修改，避免打包所有改变后无法定位效果。
4. **暂不选 G1 的容忍百分比 X。** 当前确定性已经满足 16/20 胜出，但总体时延和未完成数仍失败；仅放宽平均阈值并不会解决场景 9。新协议应在训练前确定，保留失控拥塞检查。
5. **checkpoint IO 单独作为工程项。** 已测原 300 轮 checkpoint 约 1.88 h。降低完整保存频率可减小 IO，但需明确故障丢失窗口上限，并保留阶段/门槛的完整模型、优化器、随机流和 replay 锚点。Lite replay 已经不存完整 Report/arrival history，不能把再次删这些字段当作尚未实施的优化。
