# 场景可优化性与合理性分析（只读）

均为只读分析：未训练，未改源码、配置、checkpoint 或 G1，seed 4101 仍暂停在 ep300。所有数字来自本目录脚本的输出，或已有的冻结结果文件。

- `analyze.py`：20 个 dev 门控场景。
  - 外生到达回放，得到 busy 状态和实际负载。
  - 在环境上直接跑 hover+equal，每个场景都和冻结基线的 holding 核对一致。
  - 30 GHz 合池 SRPT 下界。
  - U2U 容量域 LP。
  - 输出：`results.json`、`scene9_busy.npz`。
- `analyze_capacity.py`：各置换需要的 U2U 转发量、U2U 速率与间距的关系、能耗界。输出：`capacity.json`。
- `analyze_upper.py`：上层对上传阶段的影响上限，用任意固定悬停位置下上传 FIFO 的精确回放估计。输出：`upper_upload.json`。

## 下界定义

- **固定部分（上传 + ready）**：悬停时，任何路由策略下这部分都相同。实测取自 equal 运行中各父任务的路由时刻。
- **计算部分**：放宽为一台 30 GHz 合池服务器，可任意拆分，U2U 零时延。
  - 高优先级面积取高优任务单独做 SRPT 的结果，总面积取全部任务做 SRPT 的结果。
  - 加权 holding ≥ 9·A_high + A_all。
- **适用范围**：对任意悬停策略成立。这个下界偏松，可能达不到。

## 论文字面 U2U 与“UAV 互相靠近”杠杆（参考论文 [11] 式 13）

- 已核对原文：B_M = 3 MHz 是 UAV 间**总**带宽，上一节“每条链路独占 3 MHz”的情形排除。论文没写带宽在链路间怎么分，这里按“同时激活的链路均分”处理（假设）；每条链路用满 P_M = 1 W（不分功率），σ² 固定 −100 dBm（= 1e-13 W，不随带宽缩放）。
- 脚本：`analyze_u2u_contraction.py`（只读，U2U 分配器只替换本进程内存对象）。输出：`u2u_contraction.json`，汇总见 `summarize_u2u_contraction.py` / `console_u2u_contraction_summary.log`。
- 校验：20 个场景现口径 hover 的 holding 与 `baselines/hover_equal_*_1.json` 一致；“论文式 + 分功率”时延与 `association.json` 一致（误差 < 1e-9）。
- 收缩族：pos(s) = c + (1−s)(P0 − c)，c 为三机质心，起点为初始位置或固定关联上传最优位置，s ∈ {0, 0.1, 0.2, 0.3, 0.4, 0.6, 0.8}；区域关联不变；固定路由本地份额 α ∈ {1/3（equal）, 1/2, 2/3}。

| 项目（20 场景均值） | 值 |
|---|---:|
| INIT 6 链路同时激活时每链路速率：现状 / 论文分功率 / 论文字面 | 4.88·4.57 / 2.91·2.75 / 3.40·3.25 Mbps |
| hover_equal 时延：现状 / 论文分功率 / 论文字面 | 0.580 / 0.726（+24.8%）/ 0.599（+3.3%，20/20 变差） |
| after_route：现状 / 论文字面 | 0.272 / 0.292 s |
| U2U 能耗（900 s）：现状 / 论文字面 | 1.08 / 2.89 kJ |
| 论文字面：只移到上传最优位置（s=0） | 0.587（−2.0%） |
| 论文字面：再向中心收缩（逐场景最优 s） | 0.583（再 −0.7%，15/20 有改善；最优 s 为 0–0.2） |
| 论文字面：位置杠杆合计（逐场景最优） | 0.583（−2.8%，20/20 改善）；比现状 hover_equal 高 0.5% |
| 从初始位置直接收缩（逐场景最优 s） | 论文字面 −0.6%（11/20）；现状 U2U −0.5%（10/20） |

| 最优位置最远移动 / 到达时间（20 m/周期，10 m/周期） | 66 m（32–94）/ 19 s（10–25）, 36 s（20–50） |

- **U2U 变慢主要来自分功率，而不是 3 MHz 带宽**：不分功率时，每条链路的 SNR 不因多链路而降低，hover_equal 只变差 3.3%。
- **“UAV 互相靠近”这根杠杆很小**：收缩 s = 0.1–0.2 时再降约 0.7%；s ≥ 0.3 后因上传变慢而变差（s = 0.8 时 +20%）。在论文字面 U2U 下，上层静态摆位的可达收益仍约 −2.8%，与现状（p1 + equal −2.83%）同量级。
- **能耗（公式 + 仿真）**：
  - 现口径下，900 s 推进能耗 525.9 kJ（3 × P(0) × 900 s）。
  - 推进只计部署段（每 5 s 周期计 Σ P(v)·1 s）时，保持悬停为 105.2 kJ（公式）。
  - 两者之差 420.7 kJ = 3 × P(0) × 4 s × 180，是与策略无关的常数。
  - CPU 能耗约 199 kJ，按 κf²×周期数计算，基本也与策略无关。
  - P(v) 在 10.2 m/s 取最小值 152.5 W，悬停为 194.8 W，20 m/s 为 205.2 W（公式）。
