## 三、术语与符号硬约束

### 3.1 统一术语

- 论文正文只写“大时间尺度”“小时间尺度”“物理演化步”。
- 不使用“宏观层”“微观层”描述论文算法；只有在附录的代码映射中才可保留 `macro`、`micro` 键名。
- 地面用户到源无人机链路统一称“用户—无人机上行链路”，缩写 U2G 或 UG 二选一后全文一致。
- 无人机之间链路统一称“无人机间链路”，缩写 U2U 或 UU 二选一后全文一致。
- 一个用户任务在完成上传后可拆成多个“任务块”；拆分前的完整对象称“父任务”。
- `holding cost` 正文统一译为“加权任务驻留代价”，首次出现可在括号中注明英文。
- “真实端到端完成时延”和“训练用驻留代理代价”必须严格区分。
- “逻辑归属区域”不是物理服务边界；用户跨区后仍上传至固定源无人机。

### 3.2 核心索引

- 无人机：\(n,i,j\in\mathcal N=\{1,\ldots,N\}\)。
- 地面用户：\(k\in\mathcal K=\{1,\ldots,K\}\)。
- 优先级：\(p\in\mathcal P=\{\mathrm H,\mathrm L\}\)。
- 父任务：\(\omega\in\mathcal W\)。
- 大时间尺度周期：\(t\)。
- 周期内小时间尺度服务帧：\(r\in\{0,\ldots,17\}\)。
- 全局物理演化步：\(m\)。
- 一个小时间尺度帧内物理步：\(\ell\in\{0,\ldots,4\}\)。

不得用同一个字母同时表示任务、时间或数量。尤其不得用 \(m\) 同时表示物理步和父任务。

### 3.3 时间参数

- 大时间尺度周期：\(\Delta_{\mathrm L}=10\,\mathrm s\)。
- 部署阶段：\(\Delta_{\mathrm D}=1\,\mathrm s\)。
- 服务阶段：\(\Delta_{\mathrm V}=9\,\mathrm s\)。
- 小时间尺度帧：\(\Delta_{\mathrm S}=0.5\,\mathrm s\)。
- 物理演化步：\(\delta=0.1\,\mathrm s\)。
- 每周期前 2 个 0.5 s 时间段为部署阶段，后 18 帧为服务阶段。
- 部署阶段任务到达和用户移动继续，但 U2G、U2U、CPU 服务暂停。
- 每回合 30 个大时间尺度周期；论文必须说明这属于训练截断，不是物理吸收状态。

### 3.4 系统常量

- \(N=3\)、\(K=39\)、区域 \(1000\,\mathrm m\times1000\,\mathrm m\)、高度 \(h_{\mathrm U}=50\,\mathrm m\)。
- 初始无人机坐标分别为 \((350,350)\)、\((350,650)\)、\((650,500)\,\mathrm m\)。
- 最小无人机安全距离 \(d_{\min}=5\,\mathrm m\)。
- 单周期最大水平移动距离 \(D_{\max}=20\,\mathrm m\)。
- 航点搜索半径 \(R_{\mathrm w}=200\,\mathrm m\)，到达容差 \(0.5\,\mathrm m\)。
- U2G 总带宽 \(20\,\mathrm{MHz}\)，永久等分给全部 \(K\) 个用户；空闲用户带宽不回收。
- U2U 总带宽 \(3\,\mathrm{MHz}\)，按当前活跃有向链路数等分。
- U2G 发射功率 \(0.1\,\mathrm W\)，U2U 发射功率 \(1\,\mathrm W\)。
- 参考信道增益 \(10^{-6}\)，噪声功率 \(10^{-13}\)。
- 每架无人机最大 CPU 频率 \(10\,\mathrm{GHz}\)，计算密度 \(1000\,\mathrm{cycle/bit}\)，开关电容系数 \(10^{-28}\)。
- 系统功率预算 \(840\,\mathrm W\)；当前代码统计范围包含地面用户上行、U2U、CPU 和无人机推进能量。
- 高、低优先级权重分别为 10 和 1。

若正式配置改变，必须同步修改正文、参数表、算法、图注、附录映射和所有派生数值。

## 四、物理与队列建模约束

1. 用户—无人机关联在回合内固定；距离变化只改变上行速率。
2. U2G 每用户带宽固定为 \(B_{\mathrm{UG}}/K\)，不得写成仅在活跃用户间共享。
3. 用户侧按任务 FIFO 上传；只有父任务全部上传后才能拆分。
4. 小时间尺度动作包含高、低优先级各一个 \(N\times N\) 路由矩阵。
5. 每个路由行满足非负和为 1；实际动作由欧氏概率单纯形投影获得，不是 Softmax。
6. 本地分支直接进入源无人机计算队列；远端分支先进入有向 U2U 传输队列。
7. 远端任务块只有全部传完后才整体进入目标无人机计算队列。
8. U2U 高优先级先占容量，低优先级仅使用剩余容量。
9. 父任务完成时间由最慢任务块决定；不得把不同任务块的平均完成时间写成父任务时延。
10. 加权任务驻留代价对父任务计数，每个存活父任务每个物理步只计一次，不能在上传、传输和计算三个阶段重复计数。代码在步末服务完成后统计存活任务，故刚在本步完成的任务不计最后一个 0.1 s；正文必须写成与真实完成时延相差至多一个物理步的离散代理，不能写成逐任务严格相等。
11. 当前模型不包含结果回传、结果数据量和传播时延；正文必须明确边界，不得暗示完整双向端到端模型。
12. 计算资源由确定性加权 MaxWeight 子问题分配，不是强化学习动作；优化问题必须写成带约束 \(\mathbf f=\mathcal F_{\mathrm{MW}}(\mathbf x;0)\) 的受限策略类问题，不能把任意 CPU 频率写成被 TD3/SAC 联合搜索的变量。
13. 当前功率乘子为 0，CPU 内层不能称为动态能量价格驱动的 DVFS。

## 五、决策过程建模约束

### 5.1 Markov 性

先定义包含无人机位置、用户位置和速度、上传 FIFO、U2U 队列、计算队列、父任务/任务块阶段、业务质心、部署/服务相位、剩余部署步数、当前保持动作和实现内部记忆的增广状态 \(\mathbf x[m]\)。内部记忆至少覆盖会影响后续转移、奖励或观测的业务质心/协作流 EMA、周期累加器和边界待定经验标志。只有对这个增广的环境—封装器状态，才能陈述给定动作后下一状态分布与更早历史条件独立；不得把遗漏这些量的“物理量清单”直接称为严格 Markov 状态。

网络使用的 81 维大时间尺度输入和 48 维小时间尺度输入都是压缩观测，未包含全部上传 FIFO、父任务阶段和用户速度。不得声称二者已被证明是充分统计量。最稳妥写法：

> 本文在底层 Markov 环境上采用基于压缩观测的集中式策略；为简化算法表述，仍沿用状态、MDP/SMDP术语，但不额外声称压缩向量本身严格完备。

### 5.2 大时间尺度

- 状态局部维数 \(8N+3=27\)，全局维数 \(N(8N+3)=81\)。
- 动作原始维数 \(2N=6\)。
- 每架无人机二维动作先投影到单位圆盘，再映射为以业务质心为中心、半径 200 m 的绝对航点。
- 零动作表示以当前质心为目标，不等于无条件悬停。
- 实际位移不超过 20 m，并经过共同缩放的连续航段安全映射。
- 大时间尺度每个动作覆盖固定 10 s，可称固定持续时间 SMDP 或嵌入式 MDP；不得靠术语夸大贡献。

### 5.3 小时间尺度

- 状态维数 \(4N+4N^2=48\)。
- 原始动作维数 \(2N^2=18\)。
- Actor 的 Tanh-Gaussian 对数概率和熵定义在投影前 18 维原始动作空间。
- 单纯形投影是确定性执行解码器；不得声称 SAC 熵直接等于路由比例在单纯形上的微分熵。
- 单纯形投影只允许严格零分量，不保证训练后必然稀疏；标题和正文使用“可稀疏”，并以零分量比例、活跃链路数和 Softmax 对照实证验证。
- 一个普通经验跨 0.5 s，自举折扣为 \(\gamma_{\mathrm S}\)。
- 跨部署边界经验跨 1.5 s，组合奖励为

  \[
  \widetilde R
  =
  R_{\mathrm{last}}
  +\gamma_{\mathrm S}R_{\mathrm{dep},1}^{\mathrm H}
  +\gamma_{\mathrm S}^2R_{\mathrm{dep},2}^{\mathrm H},
  \]

  自举折扣为 \(\gamma_{\mathrm S}^3\)。

- 当前边界经验只并入部署期驻留奖励，不并入部署期溢出和功率项。必须如实写成“小时间尺度责任归因设计”，不得表述为完整部署代价。
- 经验池中小时间尺度样本实际包含 `state、raw action、reward、service-energy auxiliary、discount、next state`；大时间尺度样本实际包含 `state、action、reward、system-energy ratio、next state、done`。正文经验元组、伪代码和存储复杂度必须同时包含这些字段。
- 30 个大周期边界是 rollout 截断：大时间尺度 `done` 通常仍为 0；回合末的小时间尺度 pending 经验却以自举折扣 0 存入。必须公开说明这一不对称，并在每回合开始/结束显式清空 pending，禁止跨回合拼接。

## 六、目标、奖励和约束表述

1. 物理目标：最小化长期平均优先级加权任务驻留时间，并满足系统长期平均功率预算、运动、安全、路由单纯形和 CPU 可行性约束。均值率稳定条件必须先定义覆盖上传、U2U 和本地计算队列的总积压，不能使用未定义的笼统 \(Q[M]\)。
2. 训练代理：驻留代价先除以 10 并裁剪到 \([0,5]\)，权重 0.7；总 UAV 侧队列超过 500 Mbit 时加入有界溢出代价，权重 2；当前漂移项权重为 0。
3. 大时间尺度 TD3 奖励使用固定单边功率超限罚项：

   \[
   -0.1\{\overline c_{\mathrm P}+20[g^{\mathrm L}-1]^+\}.
   \]

4. 系统功率对偶变量初值和学习率均为 0，因此当前算法不是动态原始—对偶强化学习。
5. 能量 Critic 在乘子为 0 时不影响 Actor，只能称辅助诊断网络。
6. 固定罚函数不提供硬约束保证。只有在独立长期测试和置信区间检验通过后，才能写“经验满足功率预算”。
7. 不得把大时间尺度主 Critic 称为“时延 Critic”；它估计的是含固定功率超限罚的综合回报。
8. 不得把训练奖励直接称为毫秒时延。结果图必须分别报告真实完成任务时延、累计驻留代价、未完成任务数和截尾比例。

## 十、实验设计与防质疑要求

### 10.1 正式基线

正式比较至少包括：

- 本文大小时间尺度 TD3–投影 SAC；
- 动态业务质心部署 + 同一小时间尺度投影 SAC；
- 无协作本地计算；
- 大时间尺度 PPO + 同一小时间尺度 SAC；
- 大时间尺度 TD3 + 确定性优化/SCA 小时间尺度方法（若代码真实存在且协议一致）；
- 等比例或启发式最小队列路由；
- 去掉投影、去掉跨边界修正、去掉大小时间尺度联合训练等消融。

若现有 `CPPO-SCA` 实际使用“大时间尺度 PPO + 小时间尺度 SCA”，不得把它重命名成 TD3-SCA。

### 10.2 公平性

- 各学习基线必须使用相同训练交互预算、评估轨迹、任务到达种子、用户移动种子和模型选择规则。
- 所有方法的系统功率处理必须一致；若某条训练路径没有固定功率罚项，不能直接声称公平比较。
- 动态质心 + SAC 必须进入正式基线，而不能只作为诊断工具。
- 超参数选择只能在验证种子上完成，正式测试种子不得参与选择。

### 10.3 统计协议

- 至少 3 个独立训练种子；正式投稿更建议 5 个。
- 每个检查点使用独立的公共评估种子集合。
- 报告均值、标准差或 95% 置信区间；关键结论同时给出配对统计检验和效应量。
- 检查点选择依据必须预先固定，可采用“验证集驻留代价最小且功率置信上界不超过预算”的规则。
- 分离“训练曲线”“验证选择”“冻结模型测试”。
- 对未完成任务采用右删失分析或同时报告完成率，禁止只统计已完成任务。

### 10.4 必报指标

- 高、低优先级平均端到端时延；
- 中位数、95 分位数和 CDF；
- 加权任务驻留代价；
- 任务完成率及回合末未完成任务数；
- 本地、U2U 和计算队列的时间序列及终端增长率；
- 系统平均功率、95% 置信上界和预算违反率；
- 推进、CPU、U2U、U2G 分项能耗；
- U2U 活跃有向链路数；
- 路由矩阵零元素比例、行熵和本地处理比例；
- UAV—业务质心距离、移动距离和安全映射触发率；
- 推理时延和训练时间。

### 10.5 禁止事项

- 在正式实验完成前填写虚构数值；
- 根据单个 seed 得出显著性结论；
- 把训练奖励改善等同于真实时延改善；
- 隐藏动态质心基线优于 TD3 的诊断结果；
- 把“未观察到超预算”写成“理论保证满足约束”；
- 把仿真截断时尚未完成的任务直接丢弃；
- 对不同方法使用不同的奖励定义却不说明。
