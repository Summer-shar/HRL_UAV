# v37 负载不均衡零训练门禁结果

## 判决

**FAIL。** 增强负载空间不均衡后，60 m 协作站位相对动态质心的端到端时延收益
显著增加并超过 5 ms，但学习者实际优化的软目标 J 仍显著变差，因此不能启动正式联训。

## 匹配基准负载

在 `[12.5, 5.5, 3.5] Mbps` 及循环排列下，使用 seeds 5000--5019：

- 协作相对质心的时延收益为 4.640 ms，差值 95% CI
  `[-6.328, -2.952] ms`，19/20 个种子方向有利；
- 平均队列下降 0.321 Mbit；
- 平均功率增加 19.849 W；
- 软目标 J 增加 0.009349，95% CI `[0.007448, 0.011251]`。

## 增强不均衡负载

在总负载保持 21.5 Mbps、阶段负载改为 `[14.5, 4.5, 2.5] Mbps`
及循环排列后：

- 协作相对质心的时延收益为 **10.022 ms**，差值 95% CI
  `[-13.446, -6.597] ms`，20/20 个种子方向有利；
- 平均队列下降 **0.538 Mbit**，95% CI `[-0.712, -0.364] Mbit`，
  20/20 个种子方向有利；
- 平均功率增加 **19.998 W**，95% CI `[18.253, 21.743] W`；
- 软目标 J 增加 **0.003549**，95% CI `[0.000116, 0.006983]`，
  仅 3/20 个种子方向有利；
- 目标位置驻留占比 55.2%，阶段到位比例 95.0%，平均到位时间约 32.2 s。

## 负载旋钮的因果读数

同一批种子下，增强负载不均衡使协作时延收益增加 **5.381 ms**，95% CI
`[1.834, 8.928] ms`。因此负载空间不均衡确实放大了“转发量 × 支援链路速率改善”
这一位置价值通道；10.022 ms 不是由评估种子更换造成的。

同时，协作站位在两个场景中的功率增量几乎不变（约 20 W），使 J 差值从
`+0.009349` 缩小到 `+0.003549`，但仍未翻为负值。这说明当前失败不是轨迹缺少
物理价值，而是该物理收益在当前 `0.9×时延代理 + 0.1×能耗代理` 归一化口径下
仍不足以覆盖移动能耗代价。

## 判据核对

- [x] 时延收益大于 5 ms；
- [x] 时延差值 95% CI 排除 0；
- [ ] 软目标 J 均值改善；
- [ ] 软目标 J 差值 95% CI 排除 0；
- [x] 队列相对质心非劣。

## 结论边界

本实验已经证明当前系统中存在稳定、可解释的协作轨迹价值，但也证明当前软目标
不会稳定偏好这条 60 m 手写轨迹。若直接启动 TD3 并期待它复现该行为，学习目标与
验收目标仍然不一致，不能把未学到该行为归因于 TD3 失败。

按冻结协议，不继续调整负载、偏移或挑选种子挽救本门禁，也不启动正式联训。
下一步必须先由研究目标作出选择：保留当前 0.9/0.1 归一化软目标并降低轨迹强主张，
或在任何训练前重新定义一个真正符合“时延优先、能耗仅作有限代价报告”的目标及门禁。
