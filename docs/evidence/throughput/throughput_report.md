# V2 工程吞吐优化与验证

基线为 `137d2f1ecbcbb45689e7959170803ef945bff027`。本次继续完成中间提交 `28a1e4b` 尚未接入的实际调用链。修改限于 `hrl_v2` 的执行效率、测试和本轮验证材料；没有修改旧策略、物理源码、论文、研究配置或历史结果。

未启动 600 轮研究训练，也未启用此前 batch64/50 秒触发的备选方案。优化器测试只作用于临时模型。SAC 有效 batch 仍为 128，两次独立 critic 拟合；PPO 仍为 5 个完整 episode、900 个宏样本、150 的优化小批次和 6 个 epoch，保留原 KL 回滚规则。

当前上下文和已定向检查的下载目录未提供 `OPTIMIZATION_SPEC_CN.md` 或随附的 5 项优化原理测试。本次按用户消息明确列出的 P0/P1 实施；新增测试是实际 V2 接入测试，不冒充附件测试已运行。

## 实际补丁

| 项目 | 实际入口与实现 |
|---|---|
| P0：到达 GRU 增量推理 | `Policy.begin_episode` 为每次采集生成独立身份；`upper/lower/value` 传入身份并调用各自 `Encoder.infer`。缓存包含历史对象、游标、设备/类型和编码器参数版本；参数更新、加载/回滚、episode 变化、历史替换及游标回退触发重建。独立编码器不共享隐状态。 |
| P0：optimizer-step 前缀共享 | SAC critic/actor 及 PPO 每个优化小批次使用独立 `HistoryTape`。每个网络、每条 episode 历史只计算一次完整前缀；microbatch 对分离的隐状态叶子累积梯度，随后一次 VJP 贯穿完整历史，再执行梯度裁剪和 optimizer.step。没有截断历史梯度。目标网络与固定评价编码使用无梯度 scope。 |
| P0：PreparedBatch | SAC 在完整有效批次上解包，当前/后继共用原始历史、报告和固定图特征；PPO 在 900 行批次上准备原始数据。归一化历史可按后继后缀扩展。保留基线已有的 256 项固定 CPU 图 LRU，批内以报告身份查找以避免各网络重复结构哈希。只缓存固定输入，学习结果不跨优化器步骤复用。根批次无自引用，设备张量释放不依赖周期垃圾回收。 |
| P1：图索引 | 预构造关系索引、注意力桶、队列 padding、池化索引及设备张量，同一 microbatch 的独立网络复用这些固定数据。设备张量缓存最多保留两组 microbatch。 |
| P1：动作检查及日志 | 同一动作的支持/精度转换只做一次，供双评价网络或双目标网络使用；先在 CPU 检查 float32 转换，再传输特征。残差、目标和 KL 在循环内积累张量，末端合并同步。 |
| P1：Q 首层 | 将原拼接线性层拆成状态投影与动作投影；动作更新的 42 个候选及目标日志复用状态投影，保持原参数布局和检查点字段。 |
| P1：下层块 value | `run.collection_policy` 只在上层块提供 PPO 状态价值网络；下层块省去未用于更新的 value 前向。 |
| P1：流式评价 | `collect_metrics` 复用同一采集过程，不构造 Episode/压缩回放；场景明细继续写盘，面板使用累加器合池，不保留全部场景的父任务账本。 |

## 数值合同与一致性

物理计算和执行动作仍为 float64，神经网络仍为 CUDA float32，混合动作分布仍为 CPU float64。没有迁移分布后端，没有 TF32/混合精度变更。动作转换位置变化已比较 CPU/CUDA 特征及动作梯度；Q 首层分解和梯度累加顺序可能产生 float32 舍入差，不声称逐位一致。

基线集成测试从 Git 直接读取 `137d2f1` 的真实模块，使用非零动作输出层，避免零初始化掩盖编码器梯度。覆盖 critic/actor 输出、梯度、参数、Adam 状态、随机流、独立编码器及完整历史反传次数。另覆盖 PPO 实网小批次、完整 PPO 更新/回滚合同、图预处理、1800 帧增量历史、缓存释放、在线 Policy、执行动作梯度和流式指标。

首轮 CPU 对照的最大梯度差约 `1.4e-7`，首步 Adam 后最大参数差约 `3.1e-5`；近零梯度可被首步 Adam 放大。因此交付的是明确容差和误差记录，不是“字节完全相同”的结论。最终测试计数、逐项误差和耗时以本目录机器生成记录为准。

## 最终有界测量

### microbatch 调优

| 设置 | critic128 秒 | actor128 秒 | critic 峰值分配 MiB | actor 峰值分配 MiB |
|---|---:|---:|---:|---:|
| 基线16 | 11.267 | 6.495 | 865.1 | 523.1 |
| 优化16 | 7.445 | 4.037 | 1107.8 | 651.6 |
| 优化32候选 | 6.745 | 3.487 | 1613.6 | 971.0 |

默认仍为 microbatch16。32仅作为已测工程候选：改变分组会改变采样调用顺序，当前逐流一致性对照采用16，未自动切换。两者有效batch都为128，PPO优化小批次仍为150。未执行batch64/50秒备选配置。

CPU float64 分布和传输单项实测已列出；它们的单次耗时远小于完整网络更新，不能据此把分布预设为最大瓶颈。本次保留CPU参考后端。图构建本身未改物理特征；收益来自索引／固定张量复用，原始构建单次成本没有消失。
