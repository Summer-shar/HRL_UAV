## 2 做什么

主实验的第三阶段（SAC 微调）只训练了 100 个窗口。三个种子的验证代价里，两个在第 100 个窗口取得最低值（5.995、5.933），说明微调还没有训练到头。v2.6 做三件事：

1. **无第三阶段的消融**（只评估）：第一阶段的 SAC 配上选出的第二阶段 PPO（即主实验的 0 号候选），在 20 个测试场景上评估，用来说明第三阶段的作用。
2. **版本 ext：继续微调**。从主实验第 100 个窗口的快照（网络、优化器、经验池、随机数状态）接着训练到第 300 个窗口，其余设置与主实验的微调完全相同（温度系数 0.0025、动作网络学习率 3e-5）。每 25 个窗口保存一个候选（125、150、…、300）。HoverSAC 的悬停微调同样继续到 300 个窗口。
3. **版本 burst：继续微调，并在训练窗口中加入区域突发**。与 ext 相同，只是第 101–300 个窗口中，每个窗口以 0.5 的概率出现一次区域突发：随机选一个区域，其全部终端在一段时间内以繁忙状态的强度产生任务（与论文突发实验的做法相同，`p2/burst.py`）。开始时刻在窗口的 10%–70% 之间均匀取值（90–630 s），持续时间在窗口的 1/15–1/6 之间均匀取值（60–150 s）。突发由该窗口的到达种子确定，与策略无关。终端各自独立的忙闲切换不变。HoverSAC 同样处理。上层 PPO 不重新训练。

## 3 选择规则（与主实验相同）

每个种子、每个标签（MH-TPCO 的下层、HoverSAC）在 8 个验证场景（1–8，标称参数、无人为突发）上取单位时间系统代价最低的候选，平局取较晚的。候选池是主实验的 0、25、50、75、100 加上新的 125–300。主实验的候选留在池里，所以每个种子选中模型的验证代价不会高于现有模型。

## 4 在 ext 与 burst 之间的选择（只用验证场景）

- J：选中的 MH-TPCO 模型的验证代价，3 个种子的均值；
- B：同一批模型在“验证场景上的突发实验”（场景 1–8，期望计算需求最大的区域在 300–400 s 突发）中的单位时间系统代价，3 个种子、8 个场景的均值。

规则：

1. burst 至少有一个种子选中了新候选，且 J_burst ≤ 1.01 × J_ext，且 B_burst < B_ext：采用 burst；
2. 否则，ext 至少有一个种子选中了新候选：采用 ext；
3. 否则：保持现有结果，什么都不换。

选择写入 `DECISION.md` 和 `results/v26_decision.json`，在任何 v2.6 的测试记录产生之前完成。只有被采用的版本做测试，另一个版本不在测试场景上评估。

## 5 采用之后评估什么

对被采用版本中模型发生变化的种子，MH-TPCO 和 HoverSAC 各自重新做：20 个测试场景的标称测试、8 个场景的突发实验、16 个参数点的零样本扫参。模型没有变化的种子沿用主实验记录。全部新记录汇总到 `results/v26_records_*.json`。

## 6 需要如实说明的事

- **这是看过测试结果之后的修改。** 做 v2.6 的原因有两个：验证集上的选档数据显示微调没有训练到头；突发实验中，标称训练的模型峰值时延高于 TFOO。第二个原因来自测试场景上的结果，如实记录于此。v2.6 内部的所有选择（选候选、选版本）只用验证场景。
- **训练量不同。** 采用后，MH-TPCO 的第三阶段为 300 个窗口，候选为 13 个，论文中的 E3 和候选说明要相应修改。TFOO、TOO、NC 的下层不需要训练，上层 PPO 的训练量与候选不变。
- **如果采用 burst**：论文必须写明第三阶段的训练窗口中以 0.5 的概率加入区域突发，突发实验因此不再是“训练中没有出现过的情形”。测试用的突发（最大需求区域、300–400 s）不是训练中的固定设置，但属于同一类。
- 无论结果如何，`DECISION.md`、两个版本的全部验证记录和训练日志都保留并推送。

## 7 运行

```powershell
python tests\test_v26.py        # 不需要 torch，1–2 分钟，最后一行应为 OK
python run_v26.py go --main D:\p2_runs_v2 --out-base D:\p2_v26 --zeroshot-main D:\p2_zeroshot_v4
```

一条命令依次完成：管道冒烟 → 复制快照 → 两个版本的继续微调、验证集评估与选择、消融 → 选择版本 → 被采用版本的测试、突发实验、零样本扫参 → 汇总。状态写在 `D:\p2_v26\V26.md`，并推送到 GitHub 分支 `paper2-runs` 的 `p2_v26/`。中断后原样重跑同一条命令：已完成的任务跳过，训练从最近的快照（每 10 个窗口）继续。

耗时估计（按主实验的记录：CPU、8 个进程，微调每个窗口约 26 s）：继续微调 12 个训练任务约 2.5 小时，验证评估约 0.5 小时，测试与零样本扫参约 1.5 小时，合计约 5 小时。这是估计，不是实测。
