# 项目目标与研究上下文

整理日期：2026-10-12。下面是依据代码、配置、历史实验合同与报告整理的交接说明，不是新的实验结果。

## 研究问题

三架 UAV 为 39 个地面终端提供通信和计算服务。任务具有高/低两个优先级，先上传到关联 UAV，再动态拆分到本机与其他 UAV 计算。研究希望用 PPO 移动部署和 SAC 拆分路由，在带宽、计算、运动与安全约束下减少优先级加权任务滞留和能耗，并与 Local、equal、CVX、greedy、centroid 以及独立训练的上层基线做公平比较。

上层位置影响上传和 UAV 间通信几何；下层路由影响传输开销、计算负载和队列等待。这两个时间尺度耦合。源关联保持区域映射，并非移动到最近 UAV 就自动切换。

## 环境与控制合同

| 项目 | 当前版本共有设置或差异 |
|---|---|
| 场景 | 3 UAV、39 终端、1000 m × 1000 m 地图、50 m UAV 高度 |
| 时钟 | physical 0.1 s；lower 0.5 s；upper 5 s；每宏周期 1 s 移动 + 4 s 驻留 |
| UAV 运动 | v2.3/v2.4 最大速度 20 m/s、目标位移 20 m，地图与连续路径安全投影 |
| CPU / 上传 | 每 UAV 10 GHz；总上传带宽 20 MHz；终端上传 FIFO |
| U2U | 总带宽 3 MHz，活跃有向链路均分；固定噪声 1e-13 W；v2.4 每 UAV 1 W 总发射预算均分给活跃出链路 |
| 终端移动 | 根目录 v2.3 固定终端；speedup v2.4 Gauss-Markov，具体假设在配置 |
| 下层动作 | 两优先级 × 三 source × 三 destination；每行 simplex，support + conditional Dirichlet |
| 上层动作 | 六个 tanh Gaussian 分数，经物理运动/安全映射执行 |
| 可观测性 | 因果服务报告及已发生到达历史；隐藏活动模式不可见，属于部分可观测控制 |
| 完成 | 父任务所有正比例 fragments 完成；不能把 fragment 完成数当任务完成数 |
| 持续服务 | 队列跨 lower/upper 保留；collector 支持连续窗口，独立研究回合也可显式 reset |

成本的 holding 部分按步首未完成父任务计算，优先级权重为 10 和 1。目标组合 holding 和 upload/U2U/CPU/propulsion 能耗；v2.3/v2.4 使用 deployment-segment propulsion 并设 `propulsion_weight=0.005`。不要直接套用早期文档全时段悬停能耗公式。上下层共享物理目标，但学习奖励存在折扣聚合；具体公式应读该版本 `objective`、环境成本和 collector。

Lite 下层观测 110 维、上层 raw 729 维；上层对每个 source 的 13 个终端做 mean/max pooling。已有 full graph 路径和 `_reference` 用于其他配置或工程对照；最新 Lite 实验不等于所有配置都使用完整图网络。

## 评价与可信性

使用同场景与外生到达流做配对比较，政策随机流不是独立场景。主要观察截断加权时延/holding、物理成本、完成时延、unfinished 与能耗分项；多种子聚合、胜场和统计检验必须注明协议。G1/dev 选档不能使用 test 数据，也不能通过改变门控隐藏失败。吞吐/计时优化应验证随机流、事件 hash、参数/optimizer/replay 与数值行为保持一致。

更完整的失败、重试、诊断及历史表格见 [报告索引](history/INDEX.md)。核心源码版本关系见 [版本地图](VERSION_MAP.md)。
